Outreach engine as an MCP server

A Rust MCP server with 56 tools that finds funded startups, scores how much engineering pain they have, finds the right person's email and drafts the outreach. A human has to confirm before anything counts as sent.

Designed and built end to end: the Rust server, the scoring, the email waterfall, the Docker stack and the reply monitor.

Status: built and run end to end, locally and as a Docker stack with a reply monitor. Mailbox count since June 2026: 366 emails sent to 269 recipients, of which only 13 are replies. The agent's own sent log covers 47 of them. This page does not claim reply or conversion numbers.

Engineering and delivery

Tool server and orchestration

I built the Rust MCP server exposing 56 tools over stdio. Research, scoring, contact discovery and tracking are separate tool stages; LangGraph and CrewAI workflows also appear in the broader outreach workspace.

Compute, state and caching

Docker runs the Rust server with a persistent SQLite volume. Company analysis is cached for seven days. A Python reply monitor polls every six hours; Redis is internal to the stack, and the LangGraph intake is disabled pending database configuration.

Reliability and human review

The five-step email waterfall stops at the first accepted result and labels the final pattern fallback as unverified. A human confirms outreach before it is recorded as sent. Scoring values are routing heuristics, not calibrated probabilities.

Usage evidence

The documented call log exercises 21 of 56 tools. The historical outreach record contains 366 emails to 269 recipients since June 2026; it does not measure reply conversion or end-to-end task success.

The pipeline

Discover

Funding news, Hacker News hiring posts, startup job boards, GitHub trending, Y Combinator and Product Hunt feed one prospect list.

Enrich

Company depth analysis (cached for 7 days), tech stack lookup and a funding-signal score from public filings and news.

Score

Scores open-source issues from 0 to 100 on seven signals, and flags each as clear, contested or taken.

People

An email waterfall finds the right person and a verified address.

Route

Sends each company down one of two directions: a proposal (70%) or a job application (30%), with hard-skip and compensation filters.

Draft and send

Peer-tone proposal or candidate-tone email, with no placeholders. A human must confirm before it is logged as sent.

Track

Outreach log, contribution log, a sheet export and a reply monitor that polls the inbox every 6 hours.

Scoring

Funding signal

+40 recent SEC Form D, +20 three or more open engineering roles, +15 YC batch within 2 years, +15 Product Hunt launch within 60 days, +15 GitHub active within 14 days, +10 team of 2 to 20. At 60 or more: hunt now. 35 to 59: warm. Below 35: watch.

Issue scorer

Recency, complexity, labels, linked pull requests, comment activity, contributor count and doc quality, with a penalty for contested issues. A score of 60 or more means contribute first, then reach out.

Email waterfall

1. Email finder

Hunter email finder, accepted at a score of 50 or more.

2. GitHub profile

The public email field on the person's GitHub profile, confidence 95.

3. Pattern and verify

Six name patterns, each verified. Accepted at confidence 70 or more.

4. Domain scan

Scans every known email on the domain for a name match.

5. Unverified fallback

Best pattern, marked unverified at confidence 20, only if everything else fails.

Docker stack

networking-agent

The Rust MCP server, 56 tools over stdio, on an Ubuntu runtime image of about 190 MB, with a persistent database volume.

reply-monitor

Python service that polls the inbox every 6 hours and marks prospects as replied.

fund-watcher

Background job for company research signals. It runs, then exits.

Redis

Queue backend, internal only. A LangGraph intake agent is wired in but disabled until its database is configured.
