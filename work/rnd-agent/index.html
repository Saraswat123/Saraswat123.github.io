R&D Agent

← /work

STEM activity monitoring across campuses

R&D Agent checks three things for every campus: did it report the work, did the sheet show it, did the evidence land in Drive. It reads the daily WhatsApp report through a Moltis (OpenClaw) gateway, writes it to the Sheet database, cross-checks it against the curriculum sheet and Drive folders, and flags contradictions for a person to read. No manual cross-referencing.

Designed, built and tested the agent and its guardrails, alongside the meeting-minutes agent and under the same rules: dry run by default, deterministic extraction over model guesses, additive sheet writes only.

Status: the parser, cross-check and meeting follow-up are built and tested (20 of 20 tests), the WhatsApp gateway is linked and connected, and the first live end-to-end run is scheduled.

Engineering and delivery

Deterministic pipeline and model stage

Python parses the labelled report and cross-checks Sheets and Drive using rules. Groq summarisation with OpenRouter fallback is configured for a later language-review stage; the current documented status still has integration work pending.

Resources and access

A Moltis gateway receives reports from one allowlisted WhatsApp group. Sheets writes are additive; Drive checks file presence by default. The design keeps routine extraction and matching outside model inference.

Quality and rollout

Twenty tests pass, and 89 real meeting-sheet rows were reviewed in a dry run. The first live end-to-end run remains pending in the documented status. Labelled extraction accuracy and human-reviewed flag precision are the planned evaluation measures.

Operational limitation

Testing exposed empty group-message bodies at the gateway, with a webhook route planned. Advisory flags include the rule that fired and go to a person for review; they do not automatically correct source records.

How it works

WhatsApp capture

A gateway links as a device on the owner's own number, with no Business API and no bot added to the group. It only sees the one allowlisted group.

Field extraction

A rule-based parser reads the labelled report format (date, campus, educator, resources ready) from the message text. No model call, so no hallucination risk.

Sheet write

One row per report on a new log tab. Additive only: it never touches the educators' own tracker cells.

Cross-check

Joins the WhatsApp log with the dashboard data, the curriculum sheet and Drive folder contents on branch, month and class.

Flags and scoring

Flags contradictions, not just gaps: 100% complete with no Drive uploads, or logged activity with no matching report that month.

Meeting follow-up

Scans the R&D meetings sheet for rows never filled in, or marked completed while the notes say otherwise. Verified on live rows.

Weekly review

Runs the full cross-check once a week to catch a campus quietly falling behind. Output is advisory flags only.

Language step

A second-stage review summarises flagged items in plain language (Groq, with OpenRouter as fallback). Configured, integration next.

Guardrails

Scope

Direct messages disabled. One allowlisted group only. It never sends a visible reply.

Sheet safety

Additive writes only. Cells starting with = + - @ are prefixed so nothing runs as a formula. Meeting flags are rule-based, not model-guessed.

Drive images

Off by default. It checks that a file exists for the month and never reads the photo. No face recognition or student identification under any configuration.

Human in the loop

Output is a flag list for a person to read, never an automatic correction. Every flag names the rule that fired.

Accuracy audit

Golden set

After a week of live reports, hand-label the correct fields, run the parser on the same messages and diff. Track extraction accuracy and miss rate.

Flag precision

Confirm each flag by hand. A false-positive rate above a set threshold pauses that rule until the logic is fixed.

What testing already found

The confirm-before-enable process caught two wrong group IDs before any message was processed, and exposed a platform limit: group message bodies log empty, so a webhook route is planned.
